# Proposal

## Why

`openspec/specs/` holds 110 capability folders in one flat directory, so
finding "everything about PSD I/O" or "everything about panels" means reading
all 110 names. The CLI supports a domain tree (`specs/{domain}/{capability}/`),
but the CI pin still installs 1.3.1, which predates nested discovery. Bumping
that pin to a nested-capable release flips `openspec validate --all --strict`
red: every main spec still carries the archive-generated
`TBD - created by archiving change …` Purpose placeholder, and 1.13.2 promotes
that to a strict failure. Separately, `DEVELOPING.md` documents the build
toolchain but says nothing about OpenSpec or Serena setup or the LLM-assisted
workflow, so a new contributor — human or agent — cannot reproduce the
environment the repo assumes.

## What Changes

- **Bump the OpenSpec pin** in `guards.yml` from 1.3.1 to 1.13.2 (nested
  discovery landed in 1.7.0; 1.13.2 is the version validated here).
- **Fill in 110 Purpose sections.** Replace the placeholder `## Purpose` of
  every main spec with what that capability is for, so `--strict` goes green.
- **Move the spec corpus into a 10-domain tree.** `git mv` each of the 110
  capability folders to `openspec/specs/{domain}/{capability}/spec.md` (pure
  moves; the id becomes the relative path).
- **Add the taxonomy to `openspec/config.yaml`** — a `context` string listing
  the domains, plus `rules.proposal` and `rules.specs` naming
  `{domain}/{capability}` and the mirrored delta path
  `changes/<name>/specs/{domain}/{capability}/spec.md`.
- **Introduce a `meta` domain** for repository and development-process
  capabilities (the spec corpus and agent tooling), so repository-level
  contracts have a home instead of a loose capability at the tree root.
- **Rewrite the flat paths** in the hand-written docs and memories
  (`docs/GLOSSARY.md` 99 refs, root `AGENTS.md`, `DEVELOPING.md`,
  `docs/dev/STATE.md`, `.serena/memories/`), and record the new CLI version and
  layout.
- **Document LLM-assisted development** in `DEVELOPING.md`: OpenSpec install,
  version floor and `openspec update`; Serena setup (`serena project index`,
  committed `.serena/`, `compile_commands.json` for C++); how `AGENTS.md`,
  `.opencode/`, and `.serena/` divide the work.
- **BREAKING:** a capability id changes from `<capability>` to
  `<domain>/<capability>`. Any reference to a flat spec id (docs, tooling,
  links) must be updated; external consumers keying on a flat id break.

## Capabilities

### New Capabilities

- `meta/openspec-layout`: the shape and quality contract of the `openspec/`
  corpus — the nested `{domain}/{capability}` tree, id derivation from the
  directory path, delta paths mirroring the main path, the minimum CLI version,
  the `config.yaml` taxonomy, and a real Purpose on every main spec.
- `meta/agent-onboarding`: the contract that `DEVELOPING.md` documents the
  LLM-assisted workflow, Serena requirements and setup, and OpenSpec
  installation and version requirements.

### Modified Capabilities

None. The move is a path rename with no requirement change; the 110 Purpose
edits are overview prose, not requirements. The regenerated `.opencode/`
skills and commands are generated output, not a capability.

## Impact

- **Spec corpus:** all 110 directories under `openspec/specs/` move; every
  main spec's Purpose is rewritten.
- **CI / tooling:** `.github/workflows/guards.yml` pin; `scripts/verify-fast.sh`
  is unchanged but its `--strict` step goes from red to green.
- **Config:** new tracked `openspec/config.yaml`.
- **Docs:** `docs/GLOSSARY.md` (99 flat refs, `TASK-ALLOWS-DOCS`), root
  `AGENTS.md`, `DEVELOPING.md`, `docs/dev/STATE.md`.
- **Agent tooling:** `.opencode/skills/openspec-*` and `.opencode/commands/`
  regenerated by `openspec update` (already in the tree, including the new
  `openspec-sync-specs` / `opsx-sync`); `.serena/memories/` path updates.
- **No engine code** changes; no Rust, C++, or runtime behavior is affected.
