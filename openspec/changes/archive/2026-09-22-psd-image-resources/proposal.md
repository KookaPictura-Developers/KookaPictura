## Why

The image-resource section (ICC profile, XMP, EXIF, IPTC, resolution, guides,
and more) is byte-preserved through an open→save, but nothing parses it: the ICC
profile in particular is invisible to the engine, so the app cannot report or
use it. A tolerant parser is the prerequisite for metadata/ICC integration (P6).

## What Changes

- Add `pictura_codec::decode_image_resources(&Document) -> Vec<ImageResource>`
  that parses the preserved image-resource section into typed records
  (`id`, `name`, `data`), in stored order.
- Add well-known id constants (`ICC_PROFILE` 1039, `XMP_METADATA` 1060,
  `EXIF_DATA_1` 1058, `EXIF_DATA_3` 1059, `IPTC_NAA` 1028) and a
  `Document`-level convenience for the embedded ICC profile.
- Parse tolerantly: an unknown signature, a truncated block, or trailing bytes
  is skipped without panicking; the write path is unchanged, so preserved bytes
  stay byte-for-byte.
- No rendering or pixel change; ICC conversion is a deferred follow-up.

## Capabilities

### New Capabilities

- `psd-image-resources`: parse the preserved image-resource section into typed
  records and expose the embedded ICC profile.

## Impact

- `crates/pictura-codec`: a new `image_resources.rs` module, re-exported from
  `lib.rs`; `Document.image_resources` is unchanged.
- `crates/pictura-codec/tests/fixtures/image_resources.psd` (generated by
  `scripts/generate-fixtures.py`) plus a psd-tools oracle comparing each parsed
  resource id/name/data.
- No app change, no new dependency, no `docs/` change.
