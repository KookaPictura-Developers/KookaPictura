# Design: knockout-groups

## Context

`crates/pictura-render/src/composite.rs`: `composite_layers` builds the
document-background `base` when any top-level layer below the first carries a
non-`None` knockout, and passes `Some(&base)` for index > 0, `None` at index 0
and inside groups. `composite_layer_inner`'s pass-through branch (a group with
`BlendMode::PassThrough`, opacity 255, no mask) recurses children straight onto
the running canvas; it currently passes `base = None`, so a knockout child is
inert.

`docs/05-layers/layer-groups.md:81` documents the canonical setup: a top layer
of a group with knockout punches through the grouped layers to the layer below
the group.

`psd-tools`' compositor applies knockout inside groups: probing a red Background
plus a pass-through group of green and a half-fill `knko = Deep` blue gives
`(126, 0, 128)`. The 1-LSB difference from the CPU (round vs floor) is the same
tolerance `knockout-oracle` already documents.

## Goals / Non-Goals

**Goals:**

- A knockout child of a **pass-through** group punches through the group's
  earlier children to the document background, matching the psd-tools reference.
- A document with no knockout anywhere stays byte-identical.

**Non-Goals:**

- Knockout inside an **isolated** group (non-PassThrough blend, opacity < 255,
  or a mask) — still inert.
- Nested-group shallow targets other than the document background.
- Clipping-mask bases.

## Decisions

### D1. Propagate the base through pass-through groups

In `composite_layer_inner`, the pass-through branch changes from
`composite_layer(canvas, child, doc, None)` to
`composite_layer(canvas, child, doc, base)` — the same document-background base
the group itself received. `composite_layer_inner` therefore takes the
`base: Option<&Canvas>` parameter and threads it; the isolated branch still
passes `None` to children.

### D2. Recursive presence check

`knockout_base`'s guard must detect a knockout at any depth (a child of a
pass-through group), so it becomes a recursive `has_knockout(layer)` walk over
`layer.knockout` and `layer.children`. Without this, `base` is `None` and the
new path never runs.

### D3. Calls that must not recurse

`knockout_base` composites the background with `base = None`;
`composite_knockout` renders the knockout layer with `base = None` (a knockout
group is not supported and stays a ceiling).

### D4. Fixture and reference

`generate-fixtures.py` gains a `knockout_group()` builder: red Background, a
pass-through group (`psd.create_group([...])` and, if psd-tools defaults it to
an isolated mode, set the group's `blend_mode` to pass-through) containing a
green layer and a half-fill blue layer with `knko = Deep`. The reference is
generated by the existing `psd_knockout_reference.py` (a `--out` path). The
oracle test asserts the group's typed blend is `PassThrough`, the child's
knockout is `Deep`, the composite matches the reference at tolerance 1, and the
green is punched through.

### D5. Tests

The existing `knockout_oracle.rs` gains a second test for the group fixture
(same tolerance, same self-skip), or a sibling test file. Unit tests in
`composite.rs` add a pass-through-group scene that punches green through and an
isolated-group scene that stays byte-identical.

## Risks / Trade-offs

- [psd-tools group semantics] → the probe shows the pixel target; the test
  asserts the typed `PassThrough` blend so a fixture that silently becomes
  isolated fails loudly rather than passing for the wrong reason.
- [Rounding] → tolerance 1, as in `knockout-oracle`.
- [Isolated groups] → explicitly inert; a second fixture would only prove the
  ceiling, so it is not added.
