## Context

M4 decoded adjustment layers and taught `pictura-render::composite_rgba` to
apply them over the running backdrop, but the app still exposed a single
flattened image. The shell is a C++ Qt Widgets `QMainWindow` over a Rust
`PictureView` QObject generated by cxx-qt (`crates/pictura-app/src/cxxqt_object.rs`,
`crates/pictura-app/cpp/main.cpp`). The document lives in Rust; the C++ side
owns the widgets and the canvas. This change makes that boundary carry layer
state and layer commands.

## Goals / Non-Goals

**Goals:**

- Expose the top-level layer stack (count, name, kind, visibility) to C++.
- Let the shell mutate the stack: toggle visibility, add an adjustment layer,
  remove a layer, each recompositing and notifying the shell.
- Provide in-memory encoders for the decoded adjustment subset so the app can
  construct `AdjustmentData` without the file format knowing about it.
- Prove the path headlessly with `--self-test` on a layered PSD.

**Non-Goals:**

- Editing adjustment parameters with widgets (the encoders take fixed defaults).
- Undo/redo, drag-reorder, multi-select, or layer thumbnails.
- A `QAbstractItemModel`-based Layers panel; the dock is a plain `QListWidget`.
- Moving any GUI type into `pictura-core` or adding dependencies.

## Decisions

### QObject commands own mutation; C++ owns widgets

Every mutation is an `#[qinvokable]` method on `PictureView`. It edits the Rust
`Document`, refreshes the cached `QImage`, and emits the existing `changed`
signal. C++ never touches the document; it calls a method and re-reads
`image()`/`layer_*` when `changed` arrives. This keeps `Document` ownership in
Rust and matches the existing `open`/`image`/`magic_wand` shape rather than
introducing a new model/view layer.

Alternative considered: a `QAbstractItemModel` with `dataChanged` roles (the
long-term `LayersModel` in `ARCH-003`/`PAN-001`). Rejected for M4-C as more
machinery than the scope needs; the list is rebuilt wholesale on `changed`.

### One `changed` signal, whole-image refresh

Recompositing yields a new full `QImage`; granular per-row notifications would
not avoid that work. So all three commands call `recomposite()` and the dock
rebuilds from scratch. `QSignalBlocker` around the list rebuild prevents
checkbox `itemChanged` callbacks from re-entering `set_layer_visible`.

Alternative considered: field-level signals (`layerVisibilityChanged`,
`layersChanged`). Rejected: the composited image changes for every command, so a
single signal is the honest contract.

### Encoders live in `pictura-render`, not `pictura-core`

The decoder already lives beside `composite_rgba`. Putting the matching
encoders there keeps encode/decode symmetry and lets a round-trip test prove
agreement. `pictura-core` defines `AdjustmentData` but must stay
dependency-free (no Qt, no cxx), so it cannot host app-facing constructors that
the render/app layer drives.

Alternative considered: construct `AdjustmentData` inline in `cxxqt_object.rs`.
Rejected: the byte layouts are format knowledge and belong next to the decoder,
not in the GUI bridge; also they are then unit-testable without Qt.

### Fixed defaults chosen to visibly change the composite

`adjustment_layer` uses defaults (`posterize(4)`, `threshold(128)`,
`brightness_contrast(20, 0)`, `hue_saturation(30, 0, 0)`) and Invert is
parameterless, so any added layer changes the image — which is exactly what the
self-test asserts. Parameter widgets are out of scope.

## Risks / Trade-offs

- **O(n) full recomposite per command** → acceptable for M4 fixtures; a
  cache/dirty-rect path is deferred until profiling shows it matters.
- **Full list rebuild on every `changed`** → fine for the small layer counts in
  scope; revisit with the real `LayersModel` when filtering/thumbnails land.
- **`changed` fires for non-layer changes too** (`select_all`, `deselect`,
  `magic_wand`) → the dock rebuild is idempotent and cheap, so this is accepted
  rather than adding signal variants.
- **Selection mask coupling** → adding an adjustment while a selection is active
  attaches a full-frame raster mask. Correct for the M5-C2 self-test, but a
  stale selection silently confines a later add; out of scope to guard here.
- **Encoder/decoder drift** → mitigated by the `encode_decode_round_trips` test
  in `pictura-render` asserting each key decodes back to the intended variant.
