# ADR: Project license — GPL-3.0-or-later

- **Status:** Accepted
- **Date:** 2026-09-26
- **Supersedes:** the "distribution license" open question in
  `00-overview/licensing-and-provenance.md` (`OVR-004`).

## Context

Kooka Pictura is free and open-source software that links the Qt 6 framework.
Qt is dual-licensed (LGPLv3 / GPLv3 / commercial). All other dependencies are
permissive (MIT / Apache-2.0 / BSD / ISC / Zlib / Unicode / Unlicense). A
distribution license had to be chosen that (a) is a recognised FOSS license,
(b) is compatible with the whole dependency set, and (c) does not force the
LGPL relinking/deployment gymnastics that permissive licensing of the *host*
would require.

## Decision

Kooka Pictura is licensed **GPL-3.0-or-later**.

## Consequences

- **Qt.** LGPLv3 is satisfied by GPLv3, so the project may link Qt statically or
  dynamically; it currently links the system Qt dynamically. The corresponding
  Qt source is offered upstream (`https://code.qt.io/`).
- **Third-party notices.** `THIRD-PARTY-LICENSES` (generated by
  `scripts/third-party-licenses.py`) lists every dependency's license;
  `LICENSES/` carries the GPLv3 and LGPLv3 texts; the About box names the
  license and points to the notices.
- **Enforcement.** `deny.toml` makes CI run `cargo deny check`, allowing
  permissive and GPL/LGPL-compatible licenses and rejecting AGPL/SSPL/EUPL.
- **Contributors.** Contributions are accepted under the project license, with
  the provenance attestation in `CONTRIBUTING.md`; no CLA or sign-off is
  required.
- **Not a shield.** The license governs distribution of *this* code; it does not
  affect copyright, patent, or trademark questions about the Photoshop
  compatibility target (`OVR-004`).
