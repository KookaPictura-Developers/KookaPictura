### Qt

`Qt 6.11.1`, dynamically linked: `Core`, `Gui`, `Widgets`, `Svg`, `DBus` — all
LGPLv3 (none are GPL-only modules). Verified linkage:

```
readelf -d build/pictura | grep NEEDED
  NEEDED  libQt6Core.so.6
  NEEDED  libQt6Gui.so.6
  NEEDED  libQt6Widgets.so.6
  NEEDED  libQt6Svg.so.6
```

No `RPATH`/`RUNPATH`, no `libQt6*.so` under `build/`, no
`qt_generate_deploy_app_script` / CPack / bundling step in `CMakeLists.txt`.

### Compliance gaps

- No root `LICENSE`, `NOTICE`, or `THIRD-PARTY-LICENSES` file.
- No `deny.toml`; `AGENTS.md` documents `cargo deny check` but CI guards the step
  with `if: ${{ hashFiles('deny.toml') != '' }}`
  (`.github/workflows/ci.yml:58-64`), so **it never runs**. A copyleft crate
  could land unnoticed.
- Nothing generates per-crate notices, yet Apache-2.0 §4 requires reproducing
  NOTICE text for distributed binaries.

## 2. Blocker ranking

1. **Qt 6 — the only hard dependency blocker.** LGPLv3/commercial dual. Sellable
   closed-source on the LGPLv3 **dynamic** path (§4 obligations below); static or
   bundled Qt flips to GPL-style duties; a GPL-only Qt module (Charts, Data
   Visualization, Virtual Keyboard, …) would be an instant blocker. Not currently
   used.
2. **Missing compliance artifacts / no license gate.** Not a "library" blocker,
   but a distribution blocker: no notices, no `deny.toml`, CI check disabled.
3. **Adobe marks in shipped UI strings — the real showstopper, and not a
   dependency.** See §7.

## 3. LGPLv3-dynamic: what it obligates in practice

Dynamic linking lets the app stay proprietary and needs **no source release of
our code**. The duties are:

- **Notices (§4a–c):** ship `LGPL-3.0.txt` **and** `GPL-3.0.txt` (LGPLv3
  incorporates GPLv3 by reference); show Qt's copyright where other copyrights
  appear (About box); state prominently that Qt is used under LGPLv3 with a
  pointer to its source.
- **Qt corresponding source (§4d + GPLv3 §6):** offer the **exact version's**
  source (6.11.1), including any patches we applied. Keep Qt **unpatched**; if
  patched, publish the patches. A written offer / URL valid 3 years is the
  lightweight mechanism. Do not rely on "the distro has it" — we still point to
  it.
- **Relink/replace rights:** dynamic linking to stock `libQt6*.so` satisfies
  "suitable shared library mechanism". No anti-tamper, no signed-library gate
  that blocks a swapped Qt. See §4.
- **No added restrictions (GPLv3 §7):** the EULA must not forbid relinking or
  inspecting the Qt component to debug modifications. It can still
  protect our own code.
- **Installation Information (GPLv3 §6):** only bites for a **"User Product"**
  (consumer/embedded appliance). A desktop app on a general-purpose PC does not
  trigger it.

**What stays private:** all of `pictura-app`, every Rust crate, the UI. Only
*Qt's* source is owed.

## 4. "Give users a way to replace Qt with a modified one"

Meaning: a user must be able to make the **already-compiled** binary load a
**modified, ABI-compatible** Qt `.so` instead of the vendor one, without
recompiling our app. It is a property of linking, not a feature to build.

The loader resolves Qt at runtime (see the `NEEDED` entries above), so any of
these works with no rebuild:

```bash
LD_LIBRARY_PATH=/home/user/patched-qt/lib ./pictura
LD_PRELOAD=/home/user/patched-qt/lib/libQt6Core.so.6 ./pictura
# or overwrite /usr/lib/libQt6Core.so.6
```

**What would break it** (avoid all of these):

- Static Qt, or `-Wl,-Bstatic` for Qt — no `.so` to swap.
- Bundling Qt into our install dir (`qt_generate_deploy_app_script`, AppImage) —
  the loader finds our pinned copy first.
- `RPATH` (**not** `RUNPATH`) pinning a private Qt dir: `RPATH` is searched
  *before* `LD_LIBRARY_PATH`, so it defeats the override. `RUNPATH` is searched
  after and is safe. We currently set neither.
- Anti-tamper: integrity/checksum/signature gates that refuse a differing Qt.
- A EULA clause forbidding swap/relink or debugging the Qt component
  (GPLv3 §7 voids it anyway).
- Changing the soname / refusing ABI-compatible Qt of the same major version.

**Not required:** a plugin system, a "replace Qt" button, a patchable Qt, or
letting anyone replace *our* code.

**Flatpak wrinkle:** Qt lives in the immutable `org.kde.Platform` runtime, so a
single `.so` can't be dropped in. The accepted route is that the runtime's
**source is published** (KDE does), so a user can rebuild a modified runtime.
The native `.deb`/`.rpm` path, linking the distro's Qt, has none of this
friction.

      GPL/AGPL/SSPL) so the existing CI step starts running
- [ ] Generate `THIRD-PARTY-LICENSES` in the packaging flow
- [ ] Packaging rule: never bundle or static-link Qt; no `RPATH`; no anti-tamper
- [ ] Record the decision in `OVR-004` (replaces its open question), and rebrand
      the Adobe-marked strings (§7)

## 7. Adobe trademark findings in shipped strings

Not a dependency issue, but the biggest obstacle to selling. Shipped UI uses
Adobe marks as our own labels:

- `crates/pictura-app/cpp/command_tree.cpp:765-776` — "Photoshop Help",
  "Photoshop Support Center", "Adobe Product Improvement Program",
  "About Photoshop"
- `crates/pictura-app/cpp/command_tree.cpp:159` — "Adobe PDF Presets…"
- `crates/pictura-app/cpp/frame.cpp:381,473` — file filter
  "Photoshop files (*.psd *.psb)"

Rebrand these to neutral labels. Keep Adobe/Photoshop references nominative
(compatibility statements only), in docs—not as product UI labels. See `OVR-004`.

`assets/` is 212 SVGs (icons + cursors) with no attribution strings and no

## 9. Reproduction commands

```bash
# Every license in the resolve set, and check for copyleft:
cargo metadata --format-version 1 --offline \
  | jq -r '.packages[] | "\(.license // "NONE")|\(.name)|\(.version)"' | sort -u
cargo metadata --format-version 1 --offline \
  | jq -r '.packages[] | select(.license // "" | test("GPL|AGPL|SSPL|EUPL|CC-BY-SA|MPL|CDDL")) | "\(.license)|\(.name)|\(.version)"'

# What the shipped binary actually needs, and how it resolves Qt:
readelf -d build/pictura | grep -iE 'NEEDED|RPATH|RUNPATH'
ldd build/pictura | grep -i qt

# Confirm no Qt is bundled into the build tree:
find build -name 'libQt6*.so*'
```
