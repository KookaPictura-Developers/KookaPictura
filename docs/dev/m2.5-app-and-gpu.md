# M2.5 — App Wiring + GPU Compositing

Goal: make the compositor visible in the app, and add a GPU accelerator for the
separable blend modes. **CPU stays the oracle**; GPU parity is proven, not assumed.

## Scope

In:
- `pictura-app` renders the composited layer stack when a PSD has layers
  (`pictura_render::composite_rgba`), falling back to the embedded PSD composite
  when it does not.
- A `composite_gpu(doc)` path in `pictura-render` using a wgpu compute shader for
  the **separable** blend modes plus Normal; parity with the CPU compositor within
  ±1 LSB. Non-separable modes (Hue/Saturation/Color/Luminosity) and Dissolve stay
  CPU-only for now.
- Explicit GPU-unavailable fallback to CPU.

Out (later):
- GPU execution of non-separable modes / Dissolve.
- Real-time interactive compositing, tile streaming, partial redraw.

## Task DAG

| ID | Task | Owner | Owns | Acceptance |
|---|---|---|---|---|
| M2.5-A | App wiring | agent | `crates/pictura-app/**`, `CMakeLists.txt` | Loading a layered PSD shows the composited stack; `--self-test` exercises it |
| M2.5-B | GPU compositor (separable) | agent | `crates/pictura-render/**` | `composite_gpu` matches `composite_rgba` ≤1 for separable modes; falls back cleanly |
| M2.5-C | Integrate + review | orchestrator | — | workspace green; app runs headless |

## Conventions

- `PixelBuffer` is planar; QImage needs interleaved RGBA8888 — the conversion
  lives in the app, not the renderer.
- GPU adapter/device creation must not panic when absent; return an error and let
  the caller use the CPU path (per `AGENTS.md` and `docs/01-architecture/gpu-rendering-pipeline.md`).
- Keep the CPU compositor unchanged and authoritative.

## Exit gate

- `cargo test --workspace` green, including GPU-parity tests (skipped gracefully
  if no adapter).
- `xvfb-run ./build/pictura --self-test <layered.psd>` exits 0 and shows the
  composited stack.
- `scripts/guard.sh` green.
